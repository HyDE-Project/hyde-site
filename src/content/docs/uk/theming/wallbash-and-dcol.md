## Огляд

Цей документ пояснює конфігурацію кольорів, яка використовується для оформлення HyDE. Він охоплює основні кольори, кольори тексту та акцентні кольори. Кожен колір можна вказати або в шістнадцятковому, або в форматі RGBA.

## Ідентифікатори кольорів

За замовчуванням під час **кешування шпалери** генерується 4 основні кольори, 4 кольори тексту та 9 акцентних кольорів для кожного основного кольору.

- **`dcol_mode`**: Цей ідентифікатор визначає, чи тема перебуває в темному, чи світлому режимі.
- **`dcol_pryX`**: Це основні кольори, де `X` набуває значень від 1 до 4.
- **`dcol_txtX`**: Це інвертовані основні кольори, що використовуються для тексту, де `X` набуває значень від 1 до 4.
- **`dcol_XaxY`**: Це акцентні кольори для кожного основного кольору, де `X` набуває значень від 1 до 4, а `Y` — від 1 до 9.
- **`_rgba`**: Цей суфікс вказує, що колір у форматі RGBA. Якщо суфікса немає, колір у шістнадцятковому форматі.
- **`_rgb`**: Цей суфікс вказує, що колір у форматі RGB.

## Використання

Щоб використати конфігурацію кешованого кольору:

1. Замініть префікс `dcol_` на `wallbash_`, щоб дозволити скрипту Wallbash розпізнавати й змінювати значення.
2. Розглядайте префікс `wallbash_` як заповнювач для значення домінантного кольору.
3. Обгорніть ідентифікатор кольору кутовими дужками (`<...>`), щоб позначити заміну на відповідне значення, наприклад, `<wallbash_pry1>`.
4. Використовуйте [цей приклад](https://github.com/hyde-project/hyde/tree/master/Configs/.config/hyde/wallbash) як шаблон.

Це дозволяє створювати шаблон для конфігурацій, використовуючи домінантний колір чи шпалеру, і дозволяючи скрипту Wallbash конвертувати їх за вас.

### Створення шаблону `*.dcol`

Шаблон вимагає три частини:

- Цільовий файл
- Скрипт/команда (необов'язково)
- Вміст

## Базовий формат:

```
target|command 
contents
```


:::note
**target**|**command** завжди мають бути на 1 рядку кожного файлу шаблону. Ми називатимемо це `рядком заголовка`.
:::

#### Цільовий файл

Структуруйте свій шаблон і визначте цільове розташування конфігурації. Це може бути:

- `${cacheDir}/wallbash` з подальшою обробкою скриптом.
- Очікуваний шлях, наприклад, поруч із `kitty.conf` для Kitty, який підключається через `include theme.conf`.

Використовуйте змінні середовища для динамічної обробки директорій:

- `${confDir}` = `$XDG_CONFIG_HOME` або `$HOME/.config/`
- `${cacheDir}/wallbash` = `HYDE_CACHE_DIR/wallbash` = `$HOME/.cache/hyde`

#### Необов'язковий скрипт/команда

Заповнивши цільовий файл вмістом, ви можете запустити довільні команди/скрипти для подальшої обробки. Використовуйте змінну `WALLBASH_SCRIPTS`, щоб перейти в директорію скриптів Wallbash, наприклад, `WALLBASH_SCRIPTS/your_script.sh`.

:::caution 
Додавайте шаблони лише від довірених авторів, щоб уникнути виконання шкідливого коду.
:::

#### Вміст

Це вміст файлу, що містить заповнювачі Wallbash, наприклад, `<wallbash_pry1>`.

---

Директорія `~/.config/hyde/wallbash/*` містить три основні директорії:

### always

Шаблони в `./wallbash/always/` виконуються під час:

- Перемикання теми
- Перемикання шпалери
- Перемикання режиму

Докладніше [тут](./always/README).

### theme

Шаблони в `./wallbash/theme/` виконуються під час:

- Перемикання теми
- Перемикання режиму

Докладніше [тут](./theme/README).

### scripts

Для налаштування зберігайте свої скрипти в `./wallbash/scripts`. Використовуйте змінну `$WALLBASH_SCRIPTS`, щоб перейти в цю директорію.
