Цей документ покликаний пояснити, як HyDE опрацьовує секрети, відповідність XDG, автозапуск і десктопні портали. Він призначений для того, щоб розвіяти поширену плутанину та запобігти часто повідомлюваним проблемам. Цей документ перебуває в процесі розробки й може потребувати оновлення в майбутньому.

## Секрети

**Секрет** — це будь-який фрагмент чутливих даних, які застосунок має зберігати безпечно — найчастіше пароль або токен автентифікації, який застосунок повинен зберігати між сесіями.

### Стандарт org.freedesktop.secrets

Багато Linux-застосунків покладаються на API [org.freedesktop.secrets](https://specifications.freedesktop.org/secret-service/latest/) (_скорочено_ **o.f.s.**) для зберігання та отримання облікових даних. Цей API надається реалізаціями бекенду, такими як **KDE Wallet (KWallet)** і **GNOME Keyring**. Навіть якщо лише з міркувань сумісності, у вашій системі, ймовірно, він є:

```bash
sudo pacman -Qi libsecret
```

:::tip[Як коротко працює o.f.s.]
API o.f.s. зберігає ваші паролі разом з **атрибутами пошуку**, які застосунок може запитувати через **D-Bus**. Секрети можна *розблокувати* лише коли активна сесія користувача, а *змінювати* — лише коли стан `isLocked` дорівнює `false`.
:::

### Як HyDE опрацьовує секрети за замовчуванням

У сучасному встановленні HyDE API libsecret, визначений `org.freedesktop.secrets`, присутній, оскільки **KWallet** підтягується як залежність `kio`. `kio` встановлено, оскільки **Dolphin** є типовим GUI-провідником файлів HyDE, як визначено в `pkg_core.lst`. 

Для підвищення привілеїв на рівні системи (наприклад, монтування диска або запуск Dolphin від імені root) HyDE використовує **`polkit`** як фреймворк авторизації. Графічний запит, що просить ваш пароль, надається **агентом автентифікації polkit**. Замість того щоб жорстко прив'язуватися до одного агента, стартова конфігурація HyDE викликає **`polkitkdeauth.sh`** — диспетчерський скрипт, який проходить пріоритезований список відомих агентів polkit і запускає перший знайдений у вашій системі. Пріоритетний агент — **`hyprpolkitagent`**, але в скрипті визначено запасні варіанти: **`polkit-gnome`**, **`polkit-kde`** та інші (поряд з іншими скриптами hyde-shell).

Вам потрібен лише **один** запущений агент polkit одночасно, якщо тільки у вас немає особливих намірів щодо конфігурації.

:::tip[Порада щодо KWallet]
Якщо KWallet встановлено, але він неактивний, вимкніть його через GUI KWalletManager. Це не ідеальний варіант, але залишена увімкненою неактивна служба KWallet може спричиняти нестабільність.
:::

:::tip[Проблеми із запуском старіших застосунків через rofi?]
Можливо, встановлення `xorg-xhost` вирішить вашу проблему:

```bash
sudo pacman -Sy xorg-xhost
```

Потім перезавантажте систему.
:::

1. **Служба потребує підвищення привілеїв** — Служба (наприклад, GParted або Dolphin) потребує підвищення привілеїв для виконання завдання. Система використовує політики, визначені `polkit` (і встановлені в `/usr/share/polkit-1/...`), щоб визначити, чи потребує завдання підвищених привілеїв. Якщо підвищення потрібне, той агент polkit, який запустив `polkitkdeauth.sh`, відображає запит пароля. У разі успіху службі тимчасово дозволяється підвищити привілеї.

2. **Отримання облікових даних** — Коли застосунку знову потрібні ці облікові дані, графічний агент polkit запитує ваш пароль. Це має відбуватися безперешкодно, якщо у вас немає відсутніх залежностей або неправильної конфігурації через [неправильне встановлення HyDE](../../getting-started/installation/).

## Відповідність XDG

[Специфікація базових директорій XDG](https://specifications.freedesktop.org/basedir-spec/latest/) визначає стандартні розташування для даних користувача, конфігурації, кешу та файлів середовища виконання. HyDE намагається дотримуватися цієї специфікації через кілька основних пакетів:

### Відповідні пакети в `pkg_core.lst`

| Пакет | Призначення |
|---|---|
| `hyprpolkitagent` | Графічний і загальний агент автентифікації для запитів підвищення привілеїв. |
| `xdg-user-dirs` | Встановлює стандартні директорії користувача (`Documents`, `Pictures` тощо) відповідно до специфікації XDG. |
| `xdg-desktop-portal-hyprland` (XDPH) | Забезпечує комунікацію D-Bus між застосунками та Hyprland. Необхідний для застосунків Flatpak — трансляція екрана, інтеграція з PipeWire та інше. |
| `xdg-desktop-portal-gtk` | Резервний портал для застосунків на базі GTK (наприклад, gnome), яким потрібна комунікація через D-Bus. |

## Автозапуск та UWSM

[UWSM](https://github.com/Vladimir-csp/uwsm) (Universal Wayland Session Manager) керує запуском застосунків, розглядаючи їх як **юніти systemd**, що дозволяє керувати певними змінними середовища. Сам по собі він дозволяє запускати скрипти на рівні служби (ще до запуску навіть Hyprland) і використовує systemd для прив'язки до наших `graphical-session-pre.target`, `graphical-session.target` та `xdg-desktop-autostart.target`, забезпечуючи (в теорії):

- Чистий досвід запуску/завершення роботи.
- Скрипти й конфігурацію HyDE, встановлені на рівні служби.
- Кращу автоматичну обробку системних ресурсів і резервних варіантів.
- Чіткішу межу між тим, що належить до *графічної сесії*, а що ні.

Чого UWSM _не_ робить:

- Не дає магічного приросту продуктивності.
- Не контейнеризує та не пісочнить усі ваші застосунки.
- Не виправляє проблеми, пов'язані з чимось поза графічною сесією, що запускає UWSM.

### Скрипти конфігурації UWSM у HyDE

HyDE постачає три конфігураційні скрипти для інтеграції з UWSM і застосування стандартів, яких він має дотримуватися:

| Скрипт | Розташування | Роль |
|---|---|---|
| `00-hyde.sh` | `$XDG_CONFIG_HOME/uwsm/env.d/` | Встановлює змінні середовища для сесії. |
| `01-gpu.sh` | `$XDG_CONFIG_HOME/uwsm/env.d/` | Змінні середовища, специфічні для GPU. |
| `00-hyde.sh` | `$XDG_CONFIG_HOME/uwsm/env-hyprland.d/` | Встановлює значення за замовчуванням для застосунків Electron, шляхів конфігурації Hyprland і резервних варіантів набору інструментів. |

:::note[Вам не потрібно редагувати ці файли]
Ці конфігураційні скрипти зроблено з певними усталеними рішеннями, щоб змінні, клавіатурні скорочення й конфігурація тем HyDE мали надійні (гарні) резервні варіанти. Якщо у вас проблеми з автозапуском, рекомендація — переконатися, що UWSM обрано у вашому менеджері входу.
:::

Зверніться до [розділу налаштування Hyprland](../../configuring/hyprland/) для точнішого контролю над тим, що відбувається під час входу в систему в HyDE.

## Десктопні портали

Десктопні портали надають ізольований (пісочниця) інтерфейс для застосунків, щоб запитувати можливості хостової системи через D-Bus — подумайте про піпетки кольору, трансляцію екрана, зберігання секретів, друк тощо. Застосунки (особливо Flatpak) зазвичай не можуть отримати доступ до цих ресурсів безпосередньо; замість цього вони мають проходити через портал.

Ви можете переглянути список порталів, встановлених у вашій системі, командою:

```bash
ls /usr/share/xdg-desktop-portal/portals/
```

### Портали, що постачаються з HyDE

| Портал | Що обробляє | Примітки |
|---|---|---|
| `hyprland.portal` | Захоплення екрана, вибір вікна, віддалений робочий стіл | Основний портал; нативний для Hyprland. |
| `gtk.portal` | Записи робочого столу, файловий провідник, безпека | Резервний варіант для застосунків GTK. Тут функціонує як вторинний обробник. |
| `kwallet.portal` | Зберігання секретів через KWallet | Присутній через ланцюжок залежностей `kio` → KWallet; не налаштовується HyDE напряму. |

Пріоритет встановлено у `/usr/share/xdg-desktop-portal/hyprland-portals.conf` — Hyprland типовий, GTK резервний. Це можна перевизначити, створивши `~/.config/xdg-desktop-portal/hyprland-portals.conf`.

:::note
Якщо застосунок повністю оминає портали (поширено для старіших нативних застосунків і деяких застосунків Electron), жодна конфігурація порталу не вплине на його поведінку. Це може пояснити, чому застосунок ігнорує вашу системну тему чи уподобання.
:::

## Перемикання тем і плутанина

Стек тем HyDE наразі охоплює *чотири* категорії застосунків, описані нижче, кожна з яких оформлюється власним механізмом. Знання того, до якої категорії належить застосунок, одразу підказує, де шукати проблему, якщо щось виглядає неправильно.

### Як працює перемикання тем

У HyDE є два окремі поняття, які користувачі часто плутають:

- **Тема** (<kbd>Super</kbd> + <kbd>Shift</kbd> + <kbd>T</kbd> або `hyde-shell theme select`) — обирає повний пакет теми: набір шпалер, GTK-архів, набір іконок, курсор, набір Kvantum і попередньо визначені перевизначення кольорів. 
- **Режим** (<kbd>Super</kbd> + <kbd>Shift</kbd> + <kbd>R</kbd>) — перемикає між режимами _wallbash_ (кольори, витягнуті наживо з поточної шпалери) і режимом _theme_ (кольори з попередньо визначеної палітри пакета теми). Це впливає на застосунки, керовані wallbash, не змінюючи саму тему. 

Обидві дії сходяться в один і той самий конвеєр. Вибір теми (`hyde-shell theme select`) відкриває засіб вибору rofi, після чого викликає `theme.switch.sh` — центральний оркестратор. Перемикання режиму (`hyde-shell wallbashtoggle -m`) відкриває засіб вибору rofi для чотирьох режимів (theme, auto, dark, light), записує вибір у стан і також викликає `theme.switch.sh`.

`theme.switch.sh` виконує основну роботу: підключає `globalcontrol.sh` для налаштування середовища, завантажує змінні теми (тема GTK, набір іконок, курсор, шрифти) і записує їх у кожен відповідний конфігураційний файл — qt5ct, qt6ct, kdeglobals, gtk-2.0, gtk-3.0, gtk-4.0, xsettingsd, перевизначення flatpak та Xresources. Потім він викликає `wallpaper.sh`, щоб встановити шпалеру теми, що, своєю чергою, запускає `color.set.sh` — рушій шаблонів wallbash. `color.set.sh` завантажує кешовані домінантні кольори (dcol) для поточної шпалери, будує sed-скрипти підстановки на основі цих кольорів і застосовує їх паралельно до кожного зареєстрованого шаблону `.dcol` і `.theme` у директоріях wallbash.

`globalcontrol.sh` — це спільний скрипт середовища, який підключається майже кожним іншим скриптом HyDE. Він встановлює шляхи XDG, завантажує збережений стан теми, експортує поточну директорію теми та режим wallbash, а також надає допоміжні функції (`pkg_installed`, `set_conf`, `get_hashmap`, `get_themes`, `toml_write`), від яких залежить решта конвеєра.

`hyde-shell` об'єднує всі ці скрипти в один ініціалізований інструмент, тож для більшості користувачів рекомендованим способом взаємодії з темами є команди `hyde-shell`, а не виклик окремих скриптів.


### Rofi

Rofi керує своїм оформленням незалежно від Qt, GTK чи Kvantum. Типові теми Rofi у HyDE зберігаються в `~/.local/share/hyde/rofi/themes/` — не редагуйте їх напряму, оскільки вони перезаписуються під час оновлень.

Перемикайте стиль Rofi за допомогою <kbd>Super</kbd> + <kbd>Shift</kbd> + <kbd>A</kbd>. Якщо потрібна власна тема Rofi, розмістіть її в `~/.config/rofi/` і зверніться до [розділу про оформлення](../../theming/wallbash-and-dcol/).

#### Застосунки Qt (Dolphin, ark та інші застосунки на кшталт kde)

Оформлюються через **Kvantum** (движок стилів) і **qt5ct** / **qt6ct** (мости налаштувань). Wallbash генерує тему Kvantum з ваших активних кольорів і записує її в `~/.config/Kvantum/`. Застосунки Qt підхоплюють це автоматично, оскільки HyDE встановлює `QT_QPA_PLATFORMTHEME=qt6ct` у середовищі сесії через конфігураційні скрипти UWSM.

Якщо застосунок Qt виглядає неоформленим, перевірте, чи встановлені `kvantum`, `qt5ct` і `qt6ct`, і чи присутня змінна середовища у вашій сесії:

```bash
echo $QT_QPA_PLATFORMTHEME  # має повернути: qt6ct
```

#### Застосунки GTK2, GTK3, GTK4 (від GParted до PavuControl)

Оформлюються переважно через **nwg-look**, який записує налаштування в `~/.gtkrc-2.0` і `~/.config/gtk-3.0/settings.ini`. Тут застосовується активний GTK-архів HyDE (файл `.tar.*` всередині пакета теми).

Відкрийте `nwg-look` або — краще — натисніть <kbd>Super</kbd> + <kbd>Shift</kbd> + <kbd>R</kbd> / запустіть `hyde-shell wallbashtoggle` і порівняйте з PavuControl або Blueman-Manager. Зміни набувають чинності під час наступного запуску застосунку. Обробка GTK4 має відповідати дизайну вашої теми, але поведінка може залежати від того, як тему було створено.

Якщо застосунок GTK4 виглядає повністю білим або ігнорує вашу тему, можливо, відсутній потрібний файл `gtk.css`, він не був згенерований належним чином, або застосунок ізольований (Flatpak) і не може його прочитати.

#### Застосунки Electron (VS Code, Spotify, Discord)

Застосунки Electron використовують власний конвеєр рендерингу Chromium і не беруть нативної участі в оформленні Qt чи GTK. Шаблони wallbash у HyDE намагаються передати кольори цим застосункам через їхній шар інтеграції з GTK з різними результатами:

- **VS Code** — wallbash може застосувати кольорову тему, якщо в редакторі активне розширення wallbash або відповідна кольорова тема.
- **Spotify** — потенційно ефективно, якщо налаштовано належне середовище Spicetify.
- **Discord** — зазвичай потребує власного клієнта (наприклад, Vencord), який читає CSS; шаблони wallbash для цього існують у спільноті.
- **Zen** — має підтримку від спільноти для скрипту wallbash (https://github.com/dim-ghub/ZenBash/tree/main) 
- **neovim** — не Electron, але також має власний плагін wallbash у розробці. (https://github.com/iamharshdabas/hyde.nvim)

:::tip
Для застосунків Electron найнадійніший підхід — шаблон wallbash, специфічний для конкретного застосунку, у `~/.config/hyde/wallbash/scripts/`. Це дозволяє wallbash передавати кольори та інші дані безпосередньо у формат конфігурації застосунку під час кожної зміни шпалери чи теми.
:::

### Застосунки Flatpak

Застосунки Flatpak працюють у пісочниці й ізольовані від більшості спільних чи системних бібліотек. Вони зазвичай мають вбудовані власні середовища виконання Qt і GTK. При чистому встановленні HyDE ви можете скористатися **Warehouse**, щоб побачити, що встановлено через Flathub, або запустити `./install_fpk.sh` у директорії `~/HyDE/Scripts/extra`, щоб налаштувати це, якщо Flathub було відхилено під час `./install.sh`. Портали дозволяють контрольовані винятки з пісочниці, і завдяки інтеграції HyDE з ширшими проєктами спільноти такі застосунки, як Spotify і Discord, залежно від встановлених клієнтів, можуть отримати вигоду від певної взаємодії з користувачем:
https://github.com/HyDE-Project/HyDE/discussions/137#discussioncomment-11918528

Оформлення через портали (наприклад, з ARC) — це чистіший довгостроковий шлях, який залежить від активності `xdg-desktop-portal-gtk` у вашій сесії.

### Висновок

Цей документ покликаний дати надійні визначення основних понять, які часто розпорошені по гілках Discord і повідомленнях користувачів. Він насамперед орієнтований на вирішення поширених проблем — теми, що не завантажуються, застосунки, які не підхоплюють кольори, запити автентифікації, що поводяться неправильно — але також має бути корисним для розробників, які хочуть зрозуміти, як внутрішні механізми HyDE взаємодіють один з одним. Якщо ви хочете розібратися глибше або оптимізувати щось, зверніться до згаданих у документі скриптів, пам'ятаючи, що багато з них тісно взаємопов'язані, і зміни можуть мати каскадний ефект.
